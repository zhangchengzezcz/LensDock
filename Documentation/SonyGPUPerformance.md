# Sony 明确坐标效果的 GPU 计算

本次优化只改变已明确给定坐标的 v6 效果渲染。厂家空间和自动匹配资格仍未确定，原始节点、保存格式、独立强度、原生优先、暗角默认规则和 RAW 绑定均不改变。没有用本次性能结果宣称新增镜头覆盖或完整目标完成。

## 改变与数学关系

此前 `LensSonyGeometryImage.m` 通过三个 `CIImageProvider` 在 CPU 生成 RGB 位移场。它们没有存入文档，但首次图像求值仍有显著生成和缓存成本；首次测得 24MP D/TCA 效果约 820 ms、进程峰值物理 footprint 约 1704 MiB，1500×1000 预览也没有避开这个成本。

现在将最多 16 组三分量节点和少量变换参数传入同一 Core Image 内核，直接计算每个目标位置的采样坐标，不再创建图像尺寸的 CPU 位移场。源码只增加数学计算，没有量化照片、降为 8 位中间结果、夹紧画面空边或改动颜色/曝光。原有有界源 ROI 和分块中间结果继续保留，防止后续小数预览变换改变画布透明度。

令 `q` 为裁切后的目标位置，`c` 为校准中心在输出空间的位置，`A` 为输出到校准空间的线性变换：

```text
d = q - c
r = length(A * d) / calibrationHalfDiagonal
sample = q + d * (deltaD + deltaCA + deltaD * deltaCA)
```

绿色的 `deltaCA=0`。这来自同一径向倍率与仿射变换的代数关系，支持裁切、缩放和八种 EXIF 方向。节点传递的是相对 1 的变化量，避免过早将微小色差变化加到 float32 的 1 上而损失精度。节点间仍为原有分段线性插值，端点规则不变；强度准备和非正倍率拒绝继续使用现有 CPU 核心。

## 正确性范围

新的 `Tests/verify-sony-gpu-coordinates.m` 对已独立验证的双精度标量核心检查实际 Core Image 坐标输出：

- 全部 2–16 节点、八种方向，包含非单调正倍率、偏心裁切、非等比预览缩放和偏移原点。
- 240 组明确数学空间，460800 个通道/坐标样本。只渲染小区域，并非完整 160MP 照片。
- 不超过 6000 像素边长的预设误差限为 0.003 输出像素；16000 像素边长为 0.008，覆盖 float32 坐标的若干 ULP。实际最大误差分别约为 0.002438、0.003209 像素。

原有 256 组常量表、16 组实际变化节点表图像对照、64 个严格恒等对象、8 组小数预览 alpha、139536 个源 ROI 样本，以及 160 组 v6 原生效果编解码/渲染继续通过。厂家坐标和真实光学依然没有因此被证明；这些是渲染实现的数值检查。

## 性能方法

`Tests/benchmark-sony-geometry.py` 使用同一当前测试程序、效果封装和其他源码，分别编译项目自身提交 `05bc52f` 的旧图像实现与当前实现。每种情况各三个独立进程，重复间交替先后顺序，串行运行。编译时将实现源码摘要写进可执行文件，防止运行旧二进制却把当前源码摘要误记为它的实现。

输入是程序生成的 6000×4000 渐变，使用固定 A6000 实际节点和明确标为假设的画幅；不读取 RAW 照片。先小区域预热输入内核并提交输出缓冲内存，随后分别测效果准备、同一图像图的首次和再次求值。输出为 RGBA8，工作格式为 RGBAf、关闭上下文中间缓存选项；系统仍可能复用已求值图像和共享编译缓存。每次结果检查全部 alpha 及 63 个位置/颜色探针。

进程峰值物理 footprint 包含 Core Image、图像中间结果、原生框架和输出缓冲，不能称为“矫正表大小”。测量不包括 RAW 解码、PXD 读写、应用启动或真实界面交互；共享驱动/编译缓存可能已经预热。首次未缓存编译的额外时间不能由下表推导。

在 Apple M5 Pro、24 GiB、macOS 27.2（26B123）上的中位数记录见 `Evidence/sony-gpu-performance.json`。这不是所有 Apple 芯片 Mac 的速度承诺，尤其不能把首次求值的改善倍数用于已有缓存的重复渲染。

| 情况 | 准备＋首次求值 ms，旧→新 | 进程峰值物理 footprint MiB，旧→新 |
| --- | --- | --- |
| 24MP，D＋TCA | 809.74 → 34.02 | 1703.38 → 830.25 |
| 1500×1000 预览，D＋TCA | 790.87 → 24.81 | 1729.31 → 902.28 |
| 中心 400×400 区域，D＋TCA | 252.10 → 6.85 | 476.19 → 199.16 |
| 24MP，仅 D | 681.09 → 34.09 | 1703.31 → 830.78 |
| 24MP，仅 TCA | 570.34 → 32.90 | 1674.96 → 801.08 |
| 24MP，矫正关闭 | 11.45 → 10.91 | 246.77 → 246.74 |

同图再次求值的 D＋TCA 时间为 14.08→14.41 ms，没有显示重复渲染提速；不要把首次求值的差别表述成所有操作都快同样倍数。旧实现首次编译和新实现首次编译的探索运行各额外出现约 280 ms 准备时间，正式交替运行没有用这些单次冷编译结果推导启动性能。

最终 35 个常规组、既有 192 组渲染、160 组明确坐标原生效果以及 Swift 检查通过；开发面板模块以 arm64、macOS 26.0 最低版本和可用性警告为错误编译通过，没有更换宿主或镜像。当前来源和构建摘要见 `Evidence/sony-gpu-regression.json`，数值及图像证据分别为 `Evidence/sony-gpu-coordinate-verification.json`、`Evidence/sony-gpu-image-verification.json`、`Evidence/sony-gpu-effect-verification.json`。

复测需要本机 Pixelmator 的 PTFoundation、Xcode 和包含基线提交的 Git 历史，运行：

```sh
python3 Tests/benchmark-sony-geometry.py
```

二进制、图像缓冲与单次原始结果均在忽略的 `Build/Development/sony-geometry-performance` 中；提交的比较证据只有参数、测量及摘要，不含照片或应用本体。
